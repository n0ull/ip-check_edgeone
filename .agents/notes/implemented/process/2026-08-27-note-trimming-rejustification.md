# Agent Note: 笔记裁剪决策的理由重评（git/CI 已纳入）

Status: implemented

## Problem

[Agent Note 约定](2026-08-14-agent-note-conventions.md)与 [notes/README.md](../../README.md) 语言约定节的裁剪决策（不建三元组、门禁从简）引用了两个已失效的事实前提：「未纳入 git 版本管理」与「项目无 git 与 CI」。实际上仓库一直受 git 追踪，且随后接入了 [.githooks pre-commit](2026-08-15-pre-commit-gate.md) 与两个 GitHub Actions 工作流（见[CI/CD 笔记](../../archived/process/2026-08-14-github-actions-cicd.md)）。前提失效使原理由不再成立：未来评审者会对着失效理由困惑，或机械执行「纳入 git 与 CI 后补三元组与完整门禁」的旧指引——前提消失不等于需求出现。

## Decision

以真实理由重评两处裁剪决策，**结论不变**（单语中文、轻量校验器维持），理由更换为：

- **不建三元组**（`.zh.md` 镜像 + `.i18n.yaml` 配对侧车）：项目单语中文、无英文读者，配对机制无人消费，创建即死重；
- **门禁从简**（不建哈希、配对、跨文档引用门）：项目规模小、决策密度低、单维护者，轻量校验器（`scripts/verify-agent-notes.mjs`，已挂 `npm test` 与 pre-commit）已覆盖实际故障面（格式漂移、状态错位），完整门禁的边际收益不抵维护成本。

**回评触发条件**（满足任一即重评是否补齐）：引入英文读者；多人并行维护笔记；发生配对/引用漂移造成的实际事故。

两篇老笔记的失效理由原地更换为上述真实理由并回本链接；本笔记不替代老笔记，仅承载理由的更换。

## Alternatives considered

- **前提失效后直接补齐三元组与完整门禁**——旧指引（「纳入 git 与 CI 后补齐」）的字面结论；但 git/CI 的存在只是解除了承载限制，并未创造需求：无英文读者、无配对漂移事故，补齐即过度工程；放弃。
- **原地改理由、不建本笔记**——理由更换无档可查，未来评审者无法区分「当代判断」与「历史遗留」；放弃。

## Consequences

裁剪决策的理由与仓库现实重新对齐；「纳入 git 与 CI 即补三元组/完整门禁」的旧指引作废，回评以真实触发条件为准。若触发条件兑现，按 [notes/README.md](../../README.md) 的三元组契约补齐。
