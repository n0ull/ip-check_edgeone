# Agent Note: 查询网页与同源回退

Status: implemented

## Problem

`ip.<域名>` 网页需要同时展示 IPv4、IPv6 与双栈判定，但浏览器页面本身只经一个协议族到达。默认域名（未绑定自定义域名）下 `4.`/`test.` 子域不存在，直接抓取必然失败——网页必须给出可用的降级路径，而不是满屏『请求失败』。

## Decision

网页（`edge-functions/index.js` 内联渲染）采用『**子域优先 + 同源回退**』抓取策略：

- JS 先请求 `https://4.<BASE>/` 与 `https://test.<BASE>/`（`BASE` 由页面 Host 推导，服务端注入）；
- 子域抓取失败（DNS 未配置、证书未签发等）时，回退到同源路径端点 `/4`、`/test`（同源携带令牌 Cookie，默认域名下可用）；
- 回退发生时显示提示条（`.hint`），说明需绑定自定义域名后才能获取精确结果；
- IPv6 卡片由双栈测试结果**派生**：`test.` 返回 IPv6 即显示该地址，IPv4 则显示『当前连接为 IPv4，未获取到 IPv6』；
- 判定徽章服务端先行注入（本次连接的协议族），JS 加载完成后以 `test.` 结果校准；
- 布局为工具站极简样式：三个字段垂直堆叠（label 在上、大字 IP 在下，状态小字置于 label 行右侧），无卡片装饰、无『本页连接』行（其信息与双栈测试行重复）。

所有响应带 `Cache-Control: no-store` 与 `Access-Control-Allow-Origin: *`（跨子域抓取需要），IP 回显不允许被缓存。

## Alternatives considered

- **仅子域抓取、失败即报错**——默认域名下网页不可用，与用户实际使用路径（先用默认域名验证）冲突；放弃。
- **仅同源路径抓取**（不请求子域）——自定义域名绑定后无法展示独立的 4./test. 结果（两协议族一次请求拿不全）；放弃。
- **静态 `index.html` + 函数仅做 API**——静态资源优先于函数路由，子域根路径将返回网页而非纯文本 IP，破坏 curl 语义；放弃，UI 全部由函数渲染。

## Consequences

网页在默认域名、未配 DNS、已绑自定义域名三种状态下都可用：前两者展示同源回退结果并提示，后者展示精确的 IPv4/双栈判定。
代价是网页依赖 JS 抓取（无 JS 时仅显示静态结构、徽章与服务端注入的判定，IP 值需 JS 填充），以及 `BASE` 推导限定入口为 `ip.<域名>`（从其他前缀打开时子域拼接错误，由同源回退兜底）。
